## Architecture
- **Client-heavy.** Most pages are `"use client"` (`app/*/*-content.tsx`); not a static export.
- **Auth gate:** `components/auth-gate.tsx` redirects to `/login` without a Supabase session (real or anonymous demo). Public: `/login`, `/signup`, `/api-docs`. `proxy.ts` only refreshes the session (`lib/supabase/middleware.ts`) and clears legacy host-only `sb-*` cookies.
- **Shared session (Jom ID):** cookie domain `.taufikhamid.com` in production (`lib/supabase/cookie-options.ts`).
- **Supabase clients:** `lib/supabase-client.ts` (browser), `lib/supabase/*` (SSR/proxy), `lib/supabase-server.ts` (service role, route handlers only). Schema `jomkomute`.
- **Shared Supabase project (`master_db`)** with other Jom apps. See BSD.
- **Browser reads/writes** use the anon/authenticated key under RLS and column grants (`lib/user-reports-client.ts`, `lib/operating-hours-client.ts`, `lib/pings-client.ts`).
- **Route handlers** (`app/api/*`) use the service role: `pings/*` (planned-trip counts), `line-history` (aggregate daily counts only), `push/subscribe|unsubscribe|check`. `push/check` is called by the Vercel cron with `CRON_SECRET`.
- **Local state:** saved routes and exceptions in `localStorage` (`lib/store.ts`, keys `transit.routes`, `transit.exceptions`); followed lines and map-layer prefs likewise.
- **Station/line data:** `lib/stations.ts` generated by `scripts/generate-stations.mjs` from GTFS (Prasarana, KTMB); `scripts/generate-operating-hours.mjs` for first/last train. Walkway interchanges curated in `lib/lines.ts`.
- **i18n:** `lib/dictionaries/{en,ms}.ts`, `lib/use-dictionary.ts`.
- **Redirects** (`next.config.ts`): `jomkomute.vercel.app` to the custom domain, `/dashboard` to `/`, `/operating-hours` to `/line-status`.

## Environment variables
| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase client |
| `SUPABASE_SERVICE_ROLE_KEY` | Server only; route handlers |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Web Push |
| `CRON_SECRET` | Authorises `/api/push/check` |
| `NEXT_PUBLIC_VERCEL_ENV` | Set from `VERCEL_ENV` in `next.config.ts` (shared cookie only in production) |

## Build, test, deploy
- `npm run dev`, `npm run build`, `npm run lint`. No test runner configured.
- Do not start the dev server in agent sessions. `TODO: confirm`
- CI: `.github/workflows/supabase-migrations.yml` applies only migration files added/changed by a push (`supabase db query --linked -f`), or one file via manual dispatch.
- Deploy: Vercel Git integration from `main`. Solo repo: commit straight to `main`.

## Constraints and risks
- Vercel Hobby limits crons to once a day, so push alerts can miss same-day transitions; an in-app fallback exists (`lib/line-status-alerts.ts`).
- Migrations are not safe to replay in full (early ones recreate `public` tables); hence changed-files-only CI.
- Anonymous reports are unmoderated.
